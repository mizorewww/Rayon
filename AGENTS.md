# Rayon Agent Guide

Rayon is an SSH / server workflow client for macOS and iOS: terminals, files, port forwards, monitoring and remote desktops (VNC, UU Remote). This guide applies to every AI agent working in this repository. `docs/architecture-review.md` is the current architecture plan.

## Principles

- **Simplicity first.** Write the least code that solves the problem. No speculative abstractions, no option flags nobody asked for, no wrappers around a single call.
- **Don't reinvent the wheel.** Before writing a parser, lock/queue, protocol codec, layout container, alert system, chart or bridge, use Apple frameworks, a dependency the project or FlowDown (`../FlowDown`) already uses, or a mature community package. When you meet an existing hand-rolled wheel in code you touch, replace it rather than extend it.
- **Native over custom.** Use system navigation, `Table`, `Picker`, `Menu`, `Form`, menu-bar commands and Dynamic Type. No private SPI, no `.opacity(0)` hidden buttons, no polling timers standing in for events.
- **Strong types and structured concurrency.** `Optional` instead of sentinel objects, `UUID` instead of string keys, `@MainActor` / `actor` / `async` instead of threads, `usleep`, `@unchecked Sendable` and `nonisolated(unsafe)`.
- **Keep every feature and setting.** Refactors change how things work, never what the user can do: no user-facing feature or setting is removed unless the user asks. The terminal is Ghostty through `Lakr233/libghostty-spm`; use its APIs rather than reimplementing them.
- **Breaking changes are allowed** when they remove legacy weight (old data formats, migrations, compatibility decoders). Delete dead code instead of keeping it "just in case".
- All code text (identifiers, comments, logs, UI strings in source) is English.

## Git

- **Atomic commits.** One logical change per commit: it builds on its own, does one thing and can be reverted on its own. Never mix a refactor, a fix and a formatting pass in one commit. Split large migrations into a sequence of buildable steps.
- Message format: `type(scope): subject` (`feat`, `fix`, `refactor`, `perf`, `chore`, `docs`, `ci`, `test`). The subject says, as a plain sentence, what is true after the commit; the body says why.
- Stage files explicitly (`git add <path>`), never `git add -A` across unrelated work. Do not commit `DerivedData/`, build output or secrets.
- Do not push, force-push, or rewrite published history unless asked.

## Layout

- `Application/Rayon` — macOS app (generated by XcodeGen from `project.yml`; regenerate with `xcodegen generate`).
- `Application/mRayon` — iOS app.
- `Foundation/*` — Swift packages: `RayonSSH` (the SSH client on SwiftNIO SSH and Citadel: connections, channels, SFTP, forwards; Docker-backed live tests in `Tests/Docker`), `RayonModule` (models, store, SSH sessions, sync, remote desktop), `RayonTerminal` (Ghostty terminal), `RayonEditor`, `RayonDesign`, `MachineStatus` / `MachineStatusView` (monitoring), `SymbolPicker`, `Keychain`.
- `Workflow/Scripts` — build, install and release scripts, behind the root `Makefile`.

## Build & Verify

- `make` lists the targets. `make build-macos` builds the Mac app (Debug bundle id `me.mizorewww.rayon.debug`, its own sandbox container), `make build-ios` the iOS app for the simulator, `make test` runs every Swift package's tests; `CONFIGURATION=Release` switches configuration. Products land in `.build/DerivedData`. Or open `App.xcworkspace`.
- Both apps take their version from `Configuration/Version.xcconfig`. `make scan-license` fails when a pinned dependency is missing from `Resources/LICENSE`; add its notice when you add a dependency.
- CI (`.github/workflows/ci.yml`) runs `make build-macos`, `make build-ios`, `make test` and `make scan-license` on every pull request; auto-merge waits for it.
- A change is done when it builds for every platform it touches, its tests pass, and the affected feature works in the running app.
- UI verification uses `cua-driver`'s background computer use only: launch with its `launch_app` (never `open`, `bring_to_front` or `delivery_mode: foreground`), look through screenshots (`get_window_state` with `include_accessibility_tree: false`), and act with background pixel clicks and key presses targeted at Rayon's pid. Don't use accessibility APIs (element indices/tokens, `type_text`, `set_value`, `invoke_menu`), System Events or global input, and never loop relaunching the app.
- Do not connect to the user's real servers or accounts for testing; use local hosts (e.g. a local `sshd` / container) or the debug preview hooks in `RayonApp.swift`.

## Style

- Swift: 4-space indentation, braces on the same line, `Type+Feature.swift` extensions, one responsibility per file. Run `Workflow/Scripts/fmt.sh` if you touched many files.
- Shell: `set -euo pipefail`, minimal, no decoration.
- Comments explain *why*, not *what*. Don't leave commented-out code or TODOs without an owner.
